# История версий

Номер версии меняется при каждой сборке `.cfe`. Правило нумерации описано в [README](README.md#версии).

## 1.3.1

- В свойствах расширения указан адрес публичного репозитория: https://github.com/urasovd/ext-1C-HotKey-Transfer-public. Код не менялся.

## 1.3.0

- Версия объекта в приёмнике: если в базе ведётся версионирование (БСП), при переносе создаётся версия объекта. Автор версии — пользователь, который переносил, в комментарии база-источник и причина. Флажок «Создать версии объектов в приёмнике» в окне переноса позволяет перенести без версий; выбор запоминается. Журнал регистрации пишется всегда.
- Приёмник более старой версии флажок не учитывает и версии не создаёт. Протокол не менялся.

## 1.2.4

- В строках регистра по умолчанию переносится объект из поля «Объект», если такое поле есть, например в «Записях о версиях объектов». Выбор в поле «Что переносить» запоминается для каждого регистра.

## 1.2.3

- Первый публичный выпуск: лицензия MIT, описание и инструкция по установке.
- Исправлено: в конфигурациях на БСП регламентное задание выключало вход служебному пользователю как неактивному, и через некоторое время приём переставал работать с ошибкой «не пустила служебный вход». Теперь служебному пользователю ставится «Срок действия не ограничен», а «Разрешить приём» возвращает выключенный вход. «Настройки» показывают, что именно мешает приёму.

## 1.2.2

- Исправлено: если служебный пользователь остался от прежней версии и его нет в справочнике «Пользователи», приём не работал, а кнопка «Разрешить приём» не показывалась. Теперь «Настройки» сообщают об этом, и кнопка добавляет пользователя в справочник.
- Несколько строк регистра с одним объектом, например версии одного документа, дают одну строку переноса.
- Поле «Что переносить» показывает «Записи регистра» и выбирается из списка, поэтому видно, что можно перенести объекты из поля строки.

## 1.2.1

- Адрес попадает в список «Куда» после успешной проверки, переносить для этого ничего не нужно. Первой в списке остаётся база последнего переноса.
- Исправлено: после «Показать пароль» кнопка «Сохранить» могла отказать с сообщением о недавно использованном пароле, и адрес не сохранялся.

## 1.2.0

- Пароль служебного входа больше не записан в коде: случайный пароль создаётся при включении приёма и хранится в данных базы.
- В настройках можно показать, указать и сменить пароль.
- При обновлении: в рабочей базе нажмите «Новый пароль», затем обновите копии из нового бэкапа или введите пароль в их настройках. Сборки с общим паролем не смогут подключиться к базам с новым.

## 1.1.1

- Список использованных адресов привязан к базе. После переноса из рабочей базы в копию новая копия не предлагает перенос сама в себя. Уже использованные адреса нужно указать один раз заново.
- Понятнее сообщение, когда адрес в настройках не сохранён.

## 1.1.0

- Форма «Настройки»: включение приёма и адрес рабочей базы.
- Адрес рабочей базы попадает в бэкап, новые копии сразу предлагают его как приёмник.
- Номер версии в заголовке окна, в настройках и в сообщении о несовместимых версиях.

## 1.0.0

- Перенос по `Alt+P` без паролей и файлов настроек.
- Полный список перед записью, записывается только отмеченное.
- Названия изменённых полей, статус «без изменений», журнал на приёмнике.
- Определение рабочей базы по имени, причина и подтверждение для неё.
- Открытие объекта из строки окна, справка по `F1`.

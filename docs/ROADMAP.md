# Планы

## Записи регистров, которые ссылаются на объект

**Статус: обсуждается, не реализовано.**

Идея: при переносе объекта предлагать записи независимых регистров сведений, где он указан в измерении, например ставки по договору. Сейчас такие записи в список не попадают. Механизм должен работать для любых объектов без списка имён регистров.

Уже решено:

- Переносятся только выбранные записи, а не все записи регистра по объекту, поэтому лишние записи на приёмнике не удаляются.
- По умолчанию ничего не отмечено: без этих записей битых ссылок не будет.
- Записи предлагаются только для объектов, выбранных пользователем, а не для найденных по связям.
- Регистры, подчинённые регистратору, не предлагаются: они переносятся с документом.

Не решено, как удобно показать и выбрать записи. Отдельная строка на каждую запись не подходит: на одной типовой базе для одного договора нашлось до 14 598 записей в одном регистре. Узкие измерения (до 5 типов) в основном прикладные, широкие в основном служебные, например версии объектов и ключи доступа, но порог отсекает и часть полезных регистров. Безопасное хранилище данных переносить нельзя ни при каком отборе.

Реализация потребует новой версии протокола.

Пока записи можно перенести из списка самого регистра: выделить строки и нажать `Alt+P`.

## Позже, если понадобится

- Кнопка «Показать отличающиеся связанные»: один уровень, без галочек по умолчанию.
- Перенос для пользователей без полных прав: своя роль, проверка права изменения каждого объекта на приёмнике и решение по RLS.
- Удаление адреса из списка «Куда».
- Единый стиль имён `ast_ПеренестиОбъект` и `ast_WSObmen`. Потребует заново опубликовать веб-сервис во всех базах.

## Не проверено

- Перенос под пользователем без полных прав: команда видна, отказ понятный.
- Откат транзакции при сбое записи.
- `https`.
- Вторая конфигурация, например ЗУП.
- Срок действия паролей служебного входа, если он настроен в базе.
